Cómo Desinfectar un WordPress Hackeado (Paso a Paso)

Sigue este procedimiento técnico paso a paso para limpiar tu instalación sin dañar la base de datos ni los datos de tus usuarios.

01

Aislar el Sitio y Generar una Copia de Seguridad Forense

Antes de modificar o eliminar cualquier archivo, es indispensable tomar una instantánea del estado actual de tu instalación. Esto previene pérdidas accidentales de pedidos de WooCommerce, entradas de blog o configuraciones críticas si algo falla durante la limpieza.

  • Descarga vía FTP o cPanel la carpeta /wp-content/ y el archivo wp-config.php.
  • Exporta un volcado completo de la base de datos SQL a través de phpMyAdmin o WP-CLI (wp db export).
  • Coloca temporalmente tu web en modo mantenimiento o bloquea peticiones externas en .htaccess dejando acceso exclusivo únicamente a tu dirección IP.
💡
Regla de Oro Forense: Nunca ejecutes herramientas automáticas de limpieza sin antes contar con el volcado SQL y los archivos respaldados localmente en tu ordenador.
02

Auditar la Integridad del Núcleo de WordPress (Core Sentinel)

Los atacantes suelen esconder puertas traseras modificando archivos legítimos de WordPress como index.php, wp-load.php o wp-settings.php.

NexaGuard Security implementa Core Sentinel, una tecnología que consulta la API de sumas de verificación criptográficas (SHA-256 Checksums) de WordPress.org para comparar byte por byte cada archivo de tu versión oficial de WordPress:

  • Si un archivo del núcleo ha sido alterado con una sola línea de código malicioso, Sentinel lo detectará de inmediato sin falsos positivos.
  • Puedes sustituir de forma segura las carpetas /wp-admin/ y /wp-includes/ descargando una versión limpia y oficial directamente desde WordPress.org.
🛡️
Aviso de Seguridad: Jamás borres la carpeta /wp-content/ ni el archivo wp-config.php, ya que allí residen tus imágenes, temas, plugins y la conexión con la base de datos.
03

Erradicar Webshells, Backdoors y Malware en Base de Datos

La carpeta /wp-content/uploads/ está diseñada únicamente para almacenar archivos estáticos (imágenes, documentos PDF, videos). Bajo ninguna circunstancia debe existir un archivo .php en este directorio.

  • Busca archivos con extensiones dobles o sospechosas como logo.php, uploader.php o cache.php dentro de las carpetas de subidas.
  • Inspecciona el contenido en busca de funciones ofuscadas de ejecución remota: eval(base64_decode(...)), gzinflate() y str_rot13().
  • Revisa en tu base de datos la tabla wp_options buscando registros con claves extrañas que contengan scripts maliciosos o iframes inyectados.
04

Rotar Claves Maestras, Activar WAF y Retirar Alertas de Google

Una vez que el malware y las webshells han sido eliminados del servidor, es imprescindible cerrar todos los accesos para impedir una reinfección automática:

  • Regenera las sales de seguridad (SALT Keys): Edita wp-config.php e introduce claves nuevas generadas con el servicio oficial de la API de WordPress (https://api.wordpress.org/secret-key/1.1/salt/). Esto cerrará todas las sesiones activas de usuarios y atacantes.
  • Cambia todas las contraseñas: Administradores de WordPress, base de datos MySQL, usuarios FTP, SFTP y credenciales del panel de hosting (cPanel, Plesk).
  • Activa el Firewall WAF de NexaGuard: Despliega reglas perimetrales para bloquear inyecciones SQL, ejecución de PHP en uploads y ataques de fuerza bruta.
  • Solicita revisión en Google Search Console: Ve a Seguridad y acciones manuales > Problemas de seguridad y presiona Solicitar revisión detallando que el malware ha sido completamente erradicado. La pantalla roja suele eliminarse en menos de 24 a 48 horas.
