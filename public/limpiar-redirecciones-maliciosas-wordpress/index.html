Cómo Limpiar Redirecciones Maliciosas en WordPress (Guía Definitiva 2026)

¿Tu web redirige a páginas de spam, falsos antivirus o sitios fraudulentos?

Las redirecciones maliciosas (asociadas a campañas como ClearFake, Balada Injector y EtherHiding) secuestran a tus visitantes móviles para desviar tráfico legítimo hacia fraudes o malware. Causan el rechazo inmediato de tus clientes y ponen en riesgo tu posicionamiento SEO en Google.

1. ¿Cómo funcionan las redirecciones maliciosas modernas?

A diferencia de los ataques antiguos que afectaban a todos los visitantes por igual, las cepas actuales de malware implementan filtros de evasión inteligente:

  • Filtro por User-Agent y Referrer: La redirección solo se ejecuta si la visita procede de un buscador como Google o Bing, y proviene de un dispositivo móvil (iOS / Android). Si entras escribiendo la URL directamente en tu PC, la web carga normal.
  • Control por Cookies y Sesiones: El código malicioso guarda una cookie en el navegador del usuario para activarse únicamente una vez cada 24 horas por visitante, haciendo que sea muy difícil de reproducir cuando el dueño del sitio intenta comprobarlo.
  • Inyecciones en bases de datos: Scripts JavaScript altamente ofuscados incrustados en la tabla wp_posts o dentro de opciones de temas en wp_options (ej. siteurl, active_plugins o scripts en header y footer).

2. Protocolo Forense para Erradicar Redirecciones

01

Inspeccionar Archivos .htaccess en Todos los Niveles

Revisa no solo el archivo .htaccess en la raíz de tu WordPress, sino también subdirectorios como wp-content/, wp-content/uploads/ y wp-includes/. Los atacantes crean archivos ocultos con directivas RewriteCond %{HTTP_USER_AGENT} que fuerzan un código de redirección HTTP 301 o 302 sin pasar por PHP.

02

Verificar Archivos de Plantilla y Funciones (header.php, functions.php)

Abre el archivo header.php y functions.php de tu tema activo. Busca llamadas remotas con etiquetas <script src="https://..."> apuntando a dominios con terminaciones sospechosas (.top, .bid, .xyz, .pw) o funciones en JavaScript con eval(String.fromCharCode(...)).

03

Desinfectar Registros en la Base de Datos (wp_options, wp_posts)

Los atacantes inyectan código JavaScript ofuscado en widgets, cabeceras personalizadas y dentro de los propios artículos. Con NexaGuard Core Sentinel escaneamos cada fila de la base de datos MySQL, purificando las inyecciones sin alterar el texto ni los formatos de tus publicaciones.

04

Eliminar Backdoors Persistentes y Blindar con Firewall WAF

Si eliminas el código de redirección pero dejas el backdoor (puerta trasera), la redirección regresará en cuestión de horas. NexaGuard localiza y erradica los archivos PHP rebeldes y despliega reglas WAF que bloquean el vector de entrada para impedir reinfecciones.

4. Preguntas Frecuentes sobre Redirecciones Maliciosas

¿Por qué la redirección solo ocurre cuando entro desde el móvil y no desde el PC?

Los ciberdelincuentes programan el malware para comprobar la cabecera User-Agent y el referente de búsqueda. Si entras directamente desde tu ordenador como administrador, la web se muestra limpia para no levantar sospechas; si entra un cliente desde un móvil o un enlace de Google, se activa la redirección hacia la estafa.

¿Puedo perder mis ventas o clientes debido a las redirecciones?

Sí. Al ser desviados a páginas fraudulentas o de spam, la tasa de rebote sube al 90%, los clientes pierden la confianza y Google puede penalizar el sitio colocándolo en su lista negra de dominios engañosos.

¿Por qué vuelven a aparecer las redirecciones después de borrarlas?

Porque el atacante dejó instalada una puerta trasera (backdoor) en carpetas como uploads o un cron job en la base de datos que regenera el código malicioso automáticamente en cuanto detecta que fue eliminado.
